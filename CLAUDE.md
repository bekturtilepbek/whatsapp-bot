# CLAUDE.md

Мультитенантная платформа WhatsApp-ботов для SMB. Greenfield, один разработчик
(+ Claude Code как основной инструмент). Один код и одна инсталляция на всех клиентов; бот — запись в БД.

Читай перед работой: @docs/ARCHITECTURE.md · @docs/FEATURES.md · @docs/DECISIONS.md

## Язык общения

Отвечай по-русски. Код, идентификаторы, коммиты — по-английски. Комментарии в коде — по-русски.

## Стек

- **services/gateway** — TypeScript + Baileys. Только транспорт: сессии, auth-state
  в Postgres, события в/из Redis Streams. Никакой бизнес-логики.
- **services/worker** — Python 3.12, async-консюмер `wa:in`: пайплайн, LLM, тулзы, handoff.
- **services/celery** — Celery worker + beat: только отложенное и периодическое
  (follow-up, авто-релиз, кампании, бэкапы). Диалоговый пайплайн через Celery не ходит.
- **services/api** — FastAPI + SQLAlchemy 2.0 async + Alembic + Pydantic v2.
- PostgreSQL 17 + pgvector · Redis 7 · Docker Compose · pip (`libs/*` через `pip install -e`).
- Качество: ruff, mypy strict, pytest + testcontainers; eslint, vitest.
- Контракт событий: `docs/contracts/events.schema.json` — единственный источник истины,
  Pydantic- и zod-модели генерируются/сверяются с ним.

## Прошлая версия продукта

Статус V1 в FEATURES.md означает: фича работала в прошлой версии продукта
(whatsapp-web.js) и её фактическое поведение — эталон. Архив старого кода хранится
у разработчика вне репозитория. Если при реализации V1-фичи детали поведения
неочевидны из docs — попроси подложить в сессию нужный файл архива
(`whatsapp.js`, `transcribe.js`, `main.py`), не изобретай поведение сам.
Код из архива не копируется — переносится только поведение.

## Грабли, оплаченные прошлой версией

- **Дедуп только атомарно.** Проверка и пометка `seen` — до любого `await`
  (ловили пятикратную отправку из-за гонки).
- **Никаких таймеров в памяти.** Только Celery `apply_async(eta=...)`. Задача при
  срабатывании перепроверяет актуальность условия; `revoke` — оптимизация, не гарантия.
- **Любой внешний вызов — с таймаутом**, иначе лок диалога висит вечно и бот немеет.
- **Лок на диалог — только с TTL.**
- **Медиа — лимит размера ДО скачивания** (16 МБ). Причина OOM прошлой версии.
- **Контакт = wa_id + lid.** WhatsApp мигрирует идентификаторы на LID; без второго
  поля история человека раздваивается.
- **Настройки бота мержатся, не перезаписываются** (сохранение одной секции не должно
  затирать остальные).
- **Исходящие идемпотентны**: `client_msg_id` от worker, gateway не шлёт дубликат при ретрае.
- **Рассылки — джиттер 20–60 с, только существующие диалоги** — главный источник банов.
- **Секреты не коммитим никогда** — ни в код, ни в примеры, ни в тесты.

## Конвенции

- Тулза бота = модуль в `libs/tools/`, включается записью в `tool_bindings`. Не форкать код под клиента.
- Ничего per-bot в коде (имена таблиц, таймзона, лимиты) — всё в `bots.settings`.
- Каждая фича из FEATURES.md закрывается тестом; пайплайн тестируется на фейковом
  транспорте, без реального WhatsApp.
- Миграции только через Alembic. Conventional Commits. Ветки от `develop`.

## Команды

```bash
make dev          # локальный стек: postgres, redis, gateway, worker, celery, api
make test         # pytest + vitest
make lint         # ruff + mypy + eslint
make migrate      # alembic upgrade head
```

## Рабочий процесс

Крупные задачи — сначала план, код после подтверждения. Одна фича из FEATURES.md за
итерацию, с тестом.
