# FEATURES.md — реестр поведения платформы

Реестр поведения продукта. Каждая фича = поведение, которое обязано работать в новой
платформе. Эталон для V1-фич — код прошлой версии (архив хранится у разработчика вне
репозитория, нужные файлы подкладываются в сессию по запросу): если описание здесь
расходится со старым кодом, прав старый код — он работал у реальных клиентов;
расхождение фиксируем в этом файле.

Легенда статуса:
- `V1` — работало в прошлой версии продукта; эталон поведения — архив старого кода
- `V1-DRIFT` — работало не у всех ботов прошлой версии (копии кода разъехались); переносим объединение, включается флагом per bot
- `PLANNED` — обсуждалось для прошлой версии, внедрено не было
- `DROP` — устарело, не переносим
- `NEW` — не существовало, проектируем с нуля

## 1. Приём и обработка входящих

| # | Фича | Статус | Заметки по реализации |
|---|------|--------|----------------------|
| 1.1 | Игнор групп (`@g.us`) и `status@broadcast` | V1 | Флаг `allow_groups` per bot — некоторым клиентам может понадобиться |
| 1.2 | Атомарная дедупликация сообщений | V1 | Проверка+пометка ДО любого `await`. В прошлой версии — `Set` в памяти; теперь Redis `SET NX` c TTL 24ч + UNIQUE `wa_msg_id` в БД |
| 1.3 | Батчинг (debounce) входящих | V1 | `batch_timeout_seconds` (по умолчанию 1с). Клиент дописывает — таймер сбрасывается, LLM вызывается один раз |
| 1.4 | Понимание цитирования (quoted context) | V1 | `resolveQuotedContext` — текст цитаты подмешивается в контент сообщения. Дорогая операция на CDP → в Baileys бесплатно (`contextInfo.quotedMessage`) |
| 1.5 | Чёрный список номеров | V1 | Сейчас `ignoredNumbers` в памяти + reload endpoint → таблица `blocked_contacts` |
| 1.6 | Рабочее время бота | V1 | `work_start_hour`/`work_end_hour`, поддержка ночных смен (start > end), TZ **захардкожен Asia/Bishkek** → вынести в `bots.timezone` |
| 1.7 | Пауза бота (`bot_enabled`) | V1 | Сообщения принимаем и логируем, но не отвечаем |
| 1.8 | Статус «печатает» | V1 | `sendStateTyping()` перед ответом + `clearState()` после |
| 1.9 | Лимит размера входящего медиа (16 МБ) | PLANNED | Обсуждали, **в коде нет ни у одного бота**. Проверять размер ДО скачивания. Причина OOM-килов |
| 1.10 | Обработка revoke / edited message | NEW | Клиент удалил или отредактировал сообщение — сейчас никак не обрабатывается |

## Скоуп и порядок работ (зафиксировано, сентябрь 2026)

**Исключено из скоупа** — вернуть только по явному запросу клиентов:
1.6 рабочие часы · 1.10 удалённые/отредактированные сообщения · 2.5 поиск товара
по присланному фото · 3.5 ответ несколькими сообщениями · 4.11 букинг Google Sheets ·
4.12 букинг Postgres (шахматка) · 5.4 алерт «менеджер не отвечает» · 5.6 праздничные
автоответы · **§7 рассылки целиком** (запрещены до реализации анти-бан-дисциплины).

**Этап 1 — живое ядро** (детально в `docs/STAGE1_CORE.md`): приём и фильтры
(1.1–1.4, 1.7, 1.8), заглушка на медиа (2.6), диалог (3.1–3.3, основной промпт из 3.6,
сбор usage из 3.9), handoff (5.1–5.3), QR/logout как API-ручки (6.1, 6.2), надёжность
(8.1, 8.2, 8.4, 8.5, 8.7, 8.8), LID в схеме контакта (9.2), таймзона per bot как поле.

**Волна 1 — медиа и устойчивость:** vision/STT/PDF (2.1–2.4) + image/pdf-промпты,
интерфейс Storage → S3 (2.7), лимит медиа (1.9), чёрный список (1.5), Celery +
follow-up (5.5), ретраи LLM, метрики и алерты (8.6), нормализация номера (9.1).

**Волна 2 — товары и тулзы:** каталог в контексте (3.4), pgvector-поиск + fallback
(4.1, 4.2), карточки товара (4.3–4.6), telegram-лиды (4.7), документы и видео
(4.8, 4.9), реестр тулзов per bot (4.13).

**Волна 3 — кабинет:** §6 целиком, кроме исключённого; в первую очередь QR-экран,
промпты с версиями (3.7, 3.8), настройки, товары, переписка, роли (6.18), онбординг
бота (6.20).

**Волна 4 — платформенный хвост:** дашборд (6.17), аудит (6.19), песочница,
экспорт/удаление данных, внешний API, интерактивные кнопки (9.3–9.10 по мере запроса).
