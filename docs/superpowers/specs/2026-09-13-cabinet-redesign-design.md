# Редизайн кабинета (Signal Console) — дизайн

**Статус:** approved · 2026-09-13
**Не привязано к пункту FEATURES.md** — визуальный слой поверх уже сданных
экранов §6 (кабинет), без изменения бизнес-логики/API.

## Контекст

ADR-009 сознательно отложил дизайн кабинета: «функциональный минимум без
вложений в визуал», решение пересматривается «когда фронт начнёт тормозить
проект» или по явному запросу — этот момент наступил. Сейчас `admin-web`
(Next.js 15, App Router, React 19) не имеет ни одной дизайн-абстракции:
один `globals.css` на голых селекторах тегов (`table`, `button`, `form
label`), `<table>`/`<button>`/`<input>` без единого класса, `ToastProvider`
стилизуется инлайн-`style`. 13 экранов, ~20 клиентских/серверных
компонентов — всё в одном визуальном состоянии «браузер по умолчанию».

Архив прошлой версии (`webhook_wb/central-admin/templates/*.html`,
Jinja/FastAPI) можно смотреть только для UX-идей (что вообще показывалось на
экране, какие данные важны) — не референс дизайна и не копируется код
(CLAUDE.md); визуальный стиль архива полностью игнорируется.

Мокап токенов и двух экранов согласован с пользователем как визуальное
направление (см. артефакт «Signal Console» в истории сессии) — этот
документ фиксирует его в спеку и добавляет то, что в мокапе не показано:
техническую архитектуру стилизации, инвентарь компонентов и экранов,
тестирование.

## Явно вне скоупа этой итерации

- **Тёмная тема.** Только светлая. Токены — CSS-переменные, чтобы тёмную
  можно было добавить позже без переписывания компонентов, но саму тему не
  делаем.
- **Полноценная адаптивность под мобильные экраны.** Desktop-first;
  подтверждено пользователем — «нужна, но не сейчас». Вёрстка не должна быть
  буквально сломана на узких экранах (используем relative units, flex/grid),
  но отдельной мобильной навигации/адаптивных таблиц не строим.
- **Скриншот-тестирование/визуальная регрессия** (Chromatic, Playwright
  visual diff и т.п.) — YAGNI при одном разработчике; полагаемся на
  существующие vitest-тесты (компонентный уровень) и живую проверку
  на docker compose (визуальный уровень, вручную).
- **Изменение API/бизнес-логики.** Чисто фронтенд-слой поверх уже
  существующих данных и эндпоинтов.
- **Кастомный `ConfirmDialog`/модалки.** Единственное текущее место
  (`ProductsTable.tsx`, удаление товара) использует `window.confirm` —
  оставляем как есть; создание accessible-модалки (focus trap, Escape,
  aria-modal) — отдельная задача, если/когда появится второй кейс.
- **`переписка` (FEATURES.md 6.14, просмотр истории сообщений клиента)** —
  экрана не существует, несмотря на то что пункт числится в FEATURES.md как
  V1: сейчас есть только карточка бота с QR/статусом сессии (`/bots/[id]`).
  Редизайн покрывает то, что реально построено; когда 6.14 будет
  реализован, он ляжет на уже готовую систему (Card/Table/PageHeader) без
  отдельного дизайн-прохода.
- **Sandbox-чат остаётся «телефоном».** `SandboxChat.tsx` — сознательно
  WhatsApp-подобный вид по прямому запросу пользователя (см. FEATURES.md
  9.6) — его внутренняя стилизация не трогается. Меняется только чрома
  вокруг: он въезжает в общий bot-scoped layout (шапка + вкладки) как любой
  другой таб.

## Визуальная система

**Токены** (CSS custom properties, объявляются один раз и пробрасываются в
`tailwind.config` через `theme.extend` — компоненты никогда не пишут hex
напрямую):

| Токен | Hex | Роль |
|---|---|---|
| `--ink` | `#1C1B19` | Основной текст |
| `--ink-soft` | `#6F6A62` | Вторичный текст, подписи |
| `--ink-faint` | `#A39C8E` | Плейсхолдеры, неактивные иконки |
| `--canvas` | `#FAF9F6` | Фон страницы |
| `--surface` | `#FFFFFF` | Фон карточек/таблиц |
| `--surface-alt` | `#F1EFEA` | Заголовки таблиц, hover строки |
| `--border` | `#E4E0D8` | Все рамки |
| `--sidebar` | `#1B1A17` | Фон бокового рельса |
| `--sidebar-ink` / `--sidebar-ink-soft` | `#EDE9E2` / `#A39C8E` | Текст в сайдбаре |
| `--accent` | `#3459B4` | Основной акцент (кнопки, ссылки, активный таб) |
| `--accent-hover` | `#274783` | Hover акцента |
| `--accent-soft` | `#E8EDF8` | Фон акцентных бейджей |
| `--success` / `--warning` / `--danger` | `#1C8A5E` / `#B7791F` / `#C0362C` | Семантика статусов (отдельно от акцента) |

**Типографика:** IBM Plex Sans (интерфейс, 400/500/600) + IBM Plex Mono
(данные: телефоны, `wa_id`, суммы, токены, таймстампы — цифры выравниваются
в колонку, кабинет транспортной платформы не притворяется обычным
маркетинговым SaaS). Шрифты грузятся через `next/font/google`
(`next/font/google`, не `<link>`-тег из мокапа-артефакта — мокап собирался
под CSP артефактов, а не под реальное Next-приложение; `next/font`
самохостит файлы шрифтов на билде, без внешнего запроса и layout shift).

**Layout:** тёмный левый сайдбар (232px, фиксированный) + светлое рабочее
поле. Радиусы небольшие (6–8px), тени почти нет — плоские карточки с
рамкой `--border`, не Material-тени.

**Сигнатурный элемент — статус-пульс.** Состояние сессии бота
(`connected`/`pending`/`disconnected`) — единственный факт, вокруг которого
уже построен весь дашборд (FEATURES.md 6.17) — визуально повторяется везде,
где встречается: список ботов, дашборд, шапка карточки бота. Живой
(«подключён») статус получает анимированное кольцо (`@keyframes
pulse-ring`, 2.2s, `prefers-reduced-motion: reduce` отключает анимацию,
оставляя статичную точку).

## Технология: Tailwind CSS

- Новые зависимости `services/admin-web`: `tailwindcss`, `postcss`,
  `autoprefixer` (+ `@tailwindcss/postcss` под Tailwind v4, если ставим
  актуальную мажорную версию — уточняется на этапе `writing-plans` по
  факту последнего стабильного релиза).
- `tailwind.config.ts`: `content` — `./app/**/*.{ts,tsx}`,
  `./components/**/*.{ts,tsx}`; `theme.extend.colors` — токены таблицы
  выше по семантическим именам (`ink`, `canvas`, `accent`, `success`, …),
  `theme.extend.fontFamily.sans`/`.mono` — прокинуты из `next/font`.
- `globals.css` схлопывается до `@tailwind base/components/utilities` +
  CSS-переменных токенов на `:root`. Текущие голые селекторы тегов (`table
  { … }`, `button { … }`, `form label { … }`) удаляются — они били бы по
  специфичности с Tailwind-классами и разъезжались бы с системой компонентов.
- Классы пишутся в JSX компонентов, не выносятся в отдельные `.module.css`
  — стандартный Tailwind-подход, минимум файлов на 20+ компонентов.

## Компонентная библиотека `components/ui/`

Новая директория — каждый существующий `*Table.tsx`/`*Form.tsx` строится на
этих примитивах вместо голой разметки. Общий принцип: примитив просто
переносит существующий видимый текст/`role`/`href` в новую разметку —
существующие vitest-тесты (`getByText`/`getByRole`) не должны знать о смене
стилизации.

| Компонент | Отвечает за |
|---|---|
| `Button` | `variant`: primary/secondary/danger; используется вместо голого `<button>` |
| `Input` / `Textarea` / `NumberField` | Консистентная рамка/фокус/padding поверх нативных полей |
| `Select` | Стилизованный нативный `<select>` (используется в фильтрах `UsageTable`, `AuditLogTable`) |
| `Switch` | Toggle вместо `<input type="checkbox">` в `BotSettingsForm` |
| `Card` | Поверхность с рамкой/радиусом — обёртка секций форм и таблиц |
| `Table` | `<div class="card overflow-x-auto"><table>…` — обёртка с общими стилями заголовка/строк; колонки с числами/id получают `font-mono` через `className` на конкретной `<td>`, отдельного `<Td variant="mono">` не заводим — YAGNI на один модификатор класса |
| `Badge` | Пилюли статусов (`owner`, `paused` и т.п.) |
| `StatusPulse` | Сигнатурный элемент — принимает `status: "connected" \| "pending" \| "disconnected"`, рендерит точку+подпись+цвет из одного места (не размазывается по компонентам условной логикой цвета) |
| `Tabs` / `TabLink` | Горизонтальные вкладки bot-scoped layout, `TabLink` — обёртка над `next/link` с `aria-current="page"` на активной |
| `PageHeader` | `title` + опциональный `subtitle` + слот действия (кнопка) в правом углу — заменяет разрозненные `<h1>`+ручной `<button>` на каждой странице |
| `EmptyState` | Заголовок + описание + опциональное действие — единый паттерн вместо текущих одиночных `<p>` |
| Toast (в `ToastProvider.tsx`) | Переезжает на токены/Card-стили; `useToast()`/`role="alert"`/`role="status"` API не меняется — меняется только JSX внутри провайдера |

## Навигация: сайдбар + bot-scoped вкладки

Сейчас: `AppHeader` — плоский `<header>` со списком `<Link>` (owner-only
пункты по `user.is_platform_owner`); `/bots/[id]` — хаб-страница с
вертикальным списком `<Link>` на шесть подстраниц.

Меняется на:
- **`AppHeader` → сайдбар.** Тот же серверный компонент (`fetchCurrentUser()`
  остаётся источником данных), та же логика видимости owner-only пунктов —
  меняется только разметка/расположение (постоянная левая колонка вместо
  верхней строки). `app/layout.tsx` оборачивает в grid `[sidebar][content]`
  вместо текущего `<body>{header}{children}</body>`.
- **`app/bots/[id]/layout.tsx` (новый файл).** Общий для всех
  `/bots/[id]/*` — единожды грузит бота (`fetchBot`), рендерит шапку (имя +
  `StatusPulse` + номер) и `Tabs` (Обзор/Промпты/Товары/Настройки/Документы/
  Чёрный список/Песочница — последняя только если `isOwner`, как сейчас в
  `BotPage`). Каждый `page.tsx` подстраницы перестаёт дублировать
  собственный `<h1>{bot.name}</h1>` — уже есть в layout. `/bots/[id]/page.tsx`
  (текущий хаб со списком ссылок) становится вкладкой «Обзор» — тем же
  `QrPanel`, без списка `<Link>`.
- URL не меняются — только разметка/группировка.

## Экраны — инвентарь

Группировка по `writing-plans` (не по одному экрану за таск — иначе 13+
одинаковых по духу тасков):

1. **Фундамент** (без видимых изменений на страницах): Tailwind +
   `tailwind.config` + токены, шрифты (`next/font`), `components/ui/`
   примитивы с собственными тестами, сайдбар-layout.
2. **Bot-scoped shell**: `app/bots/[id]/layout.tsx` + вкладки; `/bots/[id]`
   (Обзор/QR) переезжает на новый layout.
3. **Список и создание ботов**: `/bots` (`BotsTable`), `/bots/new`
   (`NewBotForm`).
4. **Диалоговые настройки бота**: `/bots/[id]/settings`
   (`BotSettingsForm` + `RenameBotForm` — оба на этой странице).
5. **Товары**: `/bots/[id]/products` (`ProductsTable`), `new`/`edit`
   (`ProductForm`).
6. **Документы и чёрный список**: `DocumentsTable`, `BlockedNumbersTable`.
7. **Промпты**: `/bots/[id]/prompts` (`PromptEditor`).
8. **Песочница**: `/bots/[id]/sandbox` — только чрома вокруг
   `SandboxChat` (сам компонент не трогаем).
9. **Платформенный раздел (owner-only)**: `/dashboard` (`DashboardTable`),
   `/users` (`UsersTable`), `/audit-log` (`AuditLogTable`), `/usage`
   (`UsageTable`).
10. **`/login`** — отдельно: без сайдбара (страница вне авторизованной
    оболочки), центрированная карточка на `--canvas`.

## Тестирование

- Каждый новый примитив `components/ui/*` — свой `*.test.tsx`
  (testing-library, как остальные компоненты проекта).
- Существующие `*.test.tsx` (BotsTable, ProductsTable, BotSettingsForm,
  UsageTable, AuditLogTable, UsersTable, DashboardTable, DocumentsTable,
  BlockedNumbersTable, NewBotForm, RenameBotForm, PromptEditor, QrPanel,
  SandboxChat, ToastProvider, login) — **не переписываются заново**, только
  чинятся по мере правки разметки; они на `getByText`/`getByRole`/`href`, не
  на классах — рефактор на примитивы не должен ломать большинство из них,
  кроме мест, где сам факт наличия/имя роли меняется (например,
  чекбокс → `Switch`, если `Switch` не рендерит `role="checkbox"` —
  тест-файл в этом случае правится тем же таском, что меняет разметку).
- Живая проверка на docker compose в конце каждой волны экранов (как
  обычно) — визуальная сверка, не автоматизируется.
- `make lint` (eslint + принесённые Tailwind-специфичные правила, если
  есть) остаётся зелёным на каждом шаге.
