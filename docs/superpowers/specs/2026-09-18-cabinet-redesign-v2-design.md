# Редизайн кабинета v2 («Панель управления») — дизайн

**Статус:** approved · 2026-09-18
**Не привязано к пункту FEATURES.md** — визуальный слой поверх уже сданных
экранов §6 (кабинет), без изменения бизнес-логики/API. Заменяет визуальную
систему первого редизайна (ADR-009, закрыт 2026-09-16) — не новый продукт,
вторая итерация того же слоя.

## Контекст

Первый редизайн (Tailwind CSS v4, тёмный сайдбар, IBM Plex Sans, «статус-
пульс» как единственный сигнатурный элемент) был доведён до конца и
смёржен — все экраны кабинета переведены на единую систему примитивов
`components/ui/`. Пользователь после этого попросил попробовать другое
визуальное направление, опираясь на CSS-систему старой версии продукта
(`webhook_wb/central-admin/templates/bot_management.html` — синий акцент,
`[data-theme]`-токены, «панель»/«стат»/«пилюля»-компоненты) — не как
UX-референс (как в первом редизайне), а буквально как визуальную основу,
по прямой просьбе.

Три мокапа согласованы с пользователем итеративно в истории сессии:
1. «Диспетчерская» — собственная реинтерпретация (латунь, «линия связи») —
   отклонена пользователем в пользу второго варианта.
2. «Панель управления» — воспроизведение системы `bot_management.html`
   (синий `#3b5bdb`, `Inter`+`tabular-nums`, светлая/тёмная тема,
   `.panel`/`.stat`/`.pill`) — **выбрана как основа**.
3. Тот же мокап, доработанный по разбору Google Stitch (микротипография,
   «воздух», глубина: `rounded-2xl`+`shadow-elevated`, иконка-в-круге для
   статуса) — **финальное согласованное направление**, этот документ его
   переносит в код.

## Явно вне скоупа этой итерации

- **Рабочая тёмная тема.** Мокап демонстрировал рабочий переключатель —
  удобно для сравнения вариантов, но включение тёмной темы в реальном
  кабинете — отдельное, более крупное решение (двойной набор токенов,
  постоянный тумблер+persist, проверка каждого экрана в обеих темах).
  **Решение**: как и в первом редизайне — токены остаются CSS-переменными
  (дёшево добавить тёмную позже), сама тёмная тема не реализуется в этой
  волне. Если пользователь захочет тёмную тему сейчас, а не позже —
  отдельный явный запрос.
- **Счётчики «Сообщений от клиентов» / «Активных клиентов» на вкладке
  «Обзор».** В мокапе — иллюстративный контент вслед за демо-примером
  Google Stitch (вымышленная стоматология), не основано на реальных
  данных платформы. Такой агрегации сегодня нет ни в одном эндпоинте
  (`usage_events` считает токены/стоимость, не количество сообщений;
  «активные клиенты» не определены). Добавление — отдельная фича с
  бэкенд-частью, не чисто визуальный проход. **Не переносится** в эту
  волну; баннер «Бот активен» переносится (использует уже существующее
  поле `bot.enabled`, FEATURES.md 1.7), плитки со статами — нет.
- Все пункты первого редизайна, которые остаются в силе без изменений:
  полноценная мобильная адаптивность (desktop-first подтверждён), визуальное
  регресс-тестирование (YAGNI), изменение API/бизнес-логики, кастомный
  `ConfirmDialog` (`window.confirm` остаётся), `SandboxChat` остаётся
  WhatsApp-подобным без изменений своей внутренней стилизации.

## Визуальная система

**Токены** — те же CSS custom properties/имена, что в первом редизайне
(чтобы не плодить новый набор идентификаторов), значения и состав меняются:

| Токен | Было (v1) | Стало (v2) | Роль |
|---|---|---|---|
| `--color-ink` | `#1C1B19` | `#1D2433` | Основной текст |
| `--color-ink-soft` | `#6F6A62` | `#5A6478` | Вторичный текст, подписи |
| `--color-ink-faint` | `#A39C8E` | `#8B93A3` | Плейсхолдеры, неактивные иконки |
| `--color-canvas` | `#FAF9F6` | `#F7F8FB` | Фон страницы |
| `--color-surface` | `#FFFFFF` | `#FFFFFF` | Фон карточек/таблиц/сайдбара (без изменений) |
| `--color-surface-alt` | `#F1EFEA` | `#F1F3F8` | Заголовки таблиц, hover строки |
| `--color-border` | `#E4E0D8` | `#E7EAF0` | Все рамки |
| `--color-accent` | `#3459B4` | `#3B5BDB` | Основной акцент |
| `--color-accent-hover` | `#274783` | `#2F49C9` | Hover акцента |
| `--color-accent-soft` | `#E8EDF8` | `#EDF0FD` | Фон акцентных бейджей, активный пункт меню |
| `--color-success` | `#1C8A5E` | `#1C8C4A` | Статус «подключён» |
| `--color-success-soft` | — (новый) | `#E6F5EC` | Фон пилюли/баннера успеха |
| `--color-warning` | `#B7791F` | `#B7791F` | Статус «подключается» (без изменений) |
| `--color-warning-soft` | — (новый) | `#FAF1E2` | Фон пилюли/бейджа «на паузе»/«подключается» |
| `--color-danger` | `#C0362C` | `#D12C3C` | Опасные действия, статус-авария |
| `--color-danger-soft` | — (новый) | `#FDECEE` | Фон опасных бейджей |

**Убираются** `--color-sidebar` / `--color-sidebar-ink` / `--color-sidebar-ink-soft`
— в v2 сайдбар светлый (`surface`/`border`, тот же текст, что в контенте),
отдельная тёмная палитра сайдбару больше не нужна. Это главное структурное
отличие от v1 на уровне токенов.

**Новые тени** (Tailwind v4 `@theme` поддерживает произвольные
`--shadow-*` токены → генерируют утилиты `shadow-*`):
```
--shadow-card: 0 1px 2px rgba(29, 36, 51, .04);
--shadow-elevated: 0 10px 24px -6px rgba(29, 36, 51, .08), 0 4px 8px -4px rgba(29, 36, 51, .04);
```
`shadow-card` — дефолт для `Card`/`Table` (было `shadow-sm`/без тени в v1).
`shadow-elevated` — точечно, для «приподнятых» состояний: карточка
QR/подключения на `QrPanel`, баннер «Бот активен».

**Радиус — двухуровневый**, без новых токенов (используются стандартные
классы Tailwind): `rounded-2xl` (16px) — карточки/панели/таблицы
(`Card`, `Table`, `EmptyState`, обёртка QR); `rounded-lg`/`rounded-xl`
(8–12px) — кнопки, поля ввода, `Switch`, `Badge`, `IconBadge`-квадрат
внутри сайдбара. Было в v1: везде одно значение (`rounded-md`, 6px).

**Типографика не меняется по составу** (тот же `IBM Plex Sans` +
`IBM Plex Mono` через `next/font/google`, самохостинг — рассуждение из
спеки v1 остаётся в силе, мокап на `Inter` собирался под CSP артефактов,
не переносится буквально). Меняется **иерархия начертаний**: заголовки
страниц/секций — `font-semibold`→`font-bold` (700), `eyebrow`-подписи
(uppercase, разрядка) получают явный `font-bold` вместо `font-semibold`,
вспомогательный текст (`hint`, описания) получает `leading-relaxed`
вместо однострочного сжатия. Числа (`font-mono`) не меняются — уже были
в v1.

**Layout:** сайдбар расширяется 232px → 272px (под новый интервал
навигации), становится светлым (`surface` + `border-r`) вместо тёмного
рельса. Активный пункт меню: было — только заливка `accent-soft`; стало —
заливка `accent-soft` **плюс** акцентная полоска 3px слева
(`border-l-[3px] border-accent`). Контентная область: `padding` чуть
щедрее (`px-11 py-8` вместо `px-8 py-7`), `PageHeader` получает
опциональный `eyebrow` (uppercase-подпись над заголовком — «Платформа»
на верхнеуровневых страницах, ничего на bot-scoped, там роль eyebrow уже
играет имя бота в шапке layout).

**Сигнатурный элемент — статус-пульс, теперь пилюля.** Было: точка +
подпись плоским текстом, кольцо на самой точке. Стало: `StatusPulse`
рендерит **пилюлю** (`rounded-full`, мягкий фон `success-soft`/
`warning-soft`/нейтральный по статусу) с точкой внутри; пульсирующее
кольцо (`@keyframes pill-pulse`, `border` вместо `box-shadow`, 2s,
`prefers-reduced-motion: reduce` отключает) — **только** у `connected`,
не у `pending`/`disconnected` (сигнал «живой активной сессии», не декор
на всём подряд). Публичный API компонента (`status: "connected" |
"pending" | "disconnected"`) не меняется — потребители (`BotsTable`,
`DashboardTable`, bot-scoped `layout.tsx`) не трогаются. Раздельная
mono-подпись сырым статусом на `DashboardTable` (найденное решение волны
9, `bot.status` рядом с пилюлей для непроходных `qr`/`reconnecting`) —
остаётся тем же паттерном снаружи `StatusPulse`, не переносится внутрь
компонента.

**Новый паттерн — «иконка в мягком круге» (`IconBadge`).** Круглый
контейнер с мягкой заливкой по варианту (`success`/`accent`/`warning`/
`danger`) и SVG-иконкой внутри. Единственный сегодняшний потребитель —
подключённое состояние `QrPanel` (замена плоской строки
пилюля+телефон+кнопка на приподнятую карточку: круг с галочкой, заголовок
«WhatsApp подключён», подпись с номером, кнопка отключения) — прямое
попадание в разбор Google Stitch («глубина» через иконку-в-круге вместо
плоской точки). Заводится как переиспользуемый примитив, а не инлайн-
разметка в `QrPanel.tsx` — тот же принцип, что и остальная библиотека:
второй потребитель найдётся (например, будущий явный «здоровый»/«есть
проблема» индикатор), переиспользование дешевле, чем копипаст разметки.

**Новый паттерн — `Banner`.** Полноширинная плашка с мягкой заливкой по
варианту, иконкой слева, заголовком+описанием и опциональным слотом
действия справа (`Switch`/кнопка). Единственный сегодняшний потребитель —
«Бот активен — отвечает на сообщения» на вкладке «Обзор» (`QrPanel`),
завязан на реальное поле `bot.enabled` (FEATURES.md 1.7 — «пауза бота»,
сейчас нигде визуально не представлено, только в `BotSettingsForm`? —
уточнение: `bot.enabled` сейчас управляется ТОЛЬКО из списка ботов через
бейдж «на паузе», отдельного тумблера в кабинете бота нет — этот баннер
станет первым UI, где это поле можно переключить не выходя со страницы
бота; уточнить у пользователя эндпоинт для PATCH при реализации, если
его ещё нет).

## Технология: без изменений в архитектуре

Tailwind CSS v4 (CSS-first `@theme`), `next/font/google` (IBM Plex Sans +
Mono), `components/ui/` как единственный источник разметки для экранов.
Меняются значения токенов в `app/globals.css`, содержимое существующих
примитивов и добавляются два новых. Ни один consumer-компонент
(`*Table.tsx`, `*Form.tsx`) не обязан меняться только из-за смены палитры
— он уже использует `<Card>`/`<Table>`/`<Button>` и получит новый вид
автоматически, когда изменится сам примитив. Это ключевое отличие
объёма работ от первого редизайна: там переход шёл от голой разметки к
примитивам (каждый экран трогался), здесь — от одного набора примитивов
к другому (трогается в основном `components/ui/`, экраны — только там,
где есть **точечные** классы в обход примитивов).

## Компонентная библиотека `components/ui/` — что меняется

| Компонент | Изменение |
|---|---|
| `Button` | Радиус `rounded-md`→`rounded-lg`; варианты primary/secondary/danger сохраняются, значения токенов подтягиваются автоматически из `@theme` |
| `Input` / `Textarea` / `NumberField` / `Select` | Радиус `rounded-md`→`rounded-lg`; фокус-кольцо на новом `accent-soft` |
| `Switch` | Токены цвета обновляются (тот же `checked:bg-accent`), без структурных изменений |
| `Card` | Радиус `rounded-lg`→`rounded-2xl`, добавляется `shadow-card` по умолчанию (в v1 тени не было вовсе) |
| `Table` | Обёртка получает тот же `rounded-2xl`+`shadow-card`, что `Card` — сейчас обёртка без тени |
| `Badge` | Радиус/токены обновляются, добавляется использование новых `*-soft` токенов вместо текущих inline-приближений |
| `StatusPulse` | Переписывается на пилюлю с пульсом только у `connected` (см. выше) — API не меняется |
| `Tabs` / `TabLink` | Без структурных изменений, токены/радиус подтягиваются |
| `PageHeader` | Добавляется опциональный проп `eyebrow?: string` — uppercase-подпись над `title` |
| `EmptyState` | Радиус `rounded-2xl`, без структурных изменений |
| **`IconBadge`** (новый) | `variant: "success" \| "accent" \| "warning" \| "danger"`, `size?: "md" \| "lg"`, слот для SVG-иконки |
| **`Banner`** (новый) | `variant` (тот же набор), иконка, `title`, `description`, опциональный `action` (React-нода, обычно `Switch` или кнопка) |
| **`SidebarNavLink`** (новый) | Найдено при подготовке плана: `Sidebar.tsx` — асинхронный Server Component (`fetchCurrentUser()`), а подсветка активного пункта требует знать текущий путь — `usePathname()`, клиентский хук, недоступен в Server Component. Тот же приём, что уже решает эту же задачу для вкладок бота — `TabLink` (`"use client"` + `usePathname()`) — но с вертикальной геометрией (левая полоска, не нижнее подчёркивание), поэтому не переиспользование `TabLink` буквально, а новый маленький примитив по той же схеме |
| `Sidebar.tsx` | Не примитив `ui/`, но меняется структурно: тёмный рельс → светлый (`surface`+`border-r`), ширина 232px→272px, ссылки навигации — теперь через `SidebarNavLink` |
| `ToastProvider.tsx` | Токены/радиус подтягиваются, структура не меняется |

## Экраны — где нужны точечные правки сверх примитивов

Большинство экранов ничего не трогают — переодеваются вместе с
примитивами. Известные точки, где есть разметка в обход примитивов
(находится по факту в начале реализации, список не исчерпывающий):

1. **`QrPanel.tsx`** — подключённое состояние переписывается на
   `IconBadge`+заголовок+подпись (было: `Card` + плоская строка); поверх
   добавляется `Banner` «Бот активен» с `Switch` на `bot.enabled` (новая
   функциональность в UI — уточнить наличие PATCH-эндпоинта на паузу,
   если отсутствует, до конца волны это блокер, не тихо пропустить).
2. **`DashboardTable.tsx`** — рядом с `StatusPulse` уже есть inline-обёртка
   (`<div className="flex items-center gap-2">`) под mono-подпись сырого
   статуса — проверить, что она по-прежнему согласуется с новой пилюлей
   визуально (скорее всего просто работает без изменений, т.к. это
   соседний элемент, не внутренняя разметка `StatusPulse`).
3. **`app/bots/[id]/layout.tsx`** — шапка бота (имя+`StatusPulse`+номер) и
   `Tabs` — использует примитивы, но стоит сверить отступы/эйброу после
   смены на светлый сайдбар (граница между сайдбаром и контентом теперь
   тоньше визуально, обе поверхности белые).
4. **`app/login/page.tsx`** — карточка входа уже на `Card`+`Input`+`Button`,
   получает новый вид автоматически; отдельно проверить читаемость на
   новом `canvas`-фоне (был кремовый, стал холоднее).

## Волны реализации

В отличие от первого редизайна (10 волн по экранам, т.к. каждый экран шёл
от нуля), здесь работы меньше: смена примитивов даёт эффект сразу везде.

1. **Фундамент**: токены в `app/globals.css`, все изменения
   `components/ui/*` (включая два новых примитива со своими тестами),
   `Sidebar.tsx`, ширина сайдбара в `app/layout.tsx`.
2. **Точечные правки**: `QrPanel.tsx` (`IconBadge`+`Banner`, включая
   бэкенд-проверку на PATCH-эндпоинт паузы бота), сверка остальных
   экранов из списка выше живым прогоном — правки по факту находок, не
   заранее расписанные таски.
3. **Финальная живая проверка** — прогон всего кабинета целиком на
   docker compose, не по одному экрану (весь объём небольшой).

## Тестирование

Как в v1: примитивы получают/обновляют свои `*.test.tsx`; существующие
тесты экранов (`getByText`/`getByRole`) не переписываются — смена
токенов/радиуса не меняет доступное дерево. Живая проверка на docker
compose в конце — визуально, не автоматизируется.

## Открытые вопросы

Нет — единственный найденный при подготовке спеки открытый вопрос
(PATCH-эндпоинт для `bot.enabled`) уже закрыт: `PATCH /bots/{id}`
(`services/api/src/api/schemas/bots.py::BotPatch`) уже принимает
`enabled: bool` — тот же паттерн, что `patchBotName` в `lib/api.ts`.
Волна 2 добавляет симметричный `patchBotEnabled(baseUrl, id, enabled)`,
backend-работы не требуется.
