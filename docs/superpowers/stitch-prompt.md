# Промпт для Google Stitch

Скопируйте текст ниже целиком в Stitch как первый запрос.

---

Спроектируй веб-кабинет (desktop-first, не мобильное приложение) для
платформы, через которую владельцы малого бизнеса (кафе, магазины,
клиники) настраивают своего WhatsApp-бота-продавца, а один администратор
платформы следит за здоровьем всех таких ботов сразу.

Тон: сдержанный операционный инструмент для одного человека, следящего за
живыми WhatsApp-подключениями десятков клиентов — не маркетинговый лендинг,
не консьюмерское приложение. Референс из мира продукта: старая версия
этого же сервиса называла шлюз к WhatsApp «телефонной станцией» — общая
метафора коммутатора/линии связи уместна, но НЕ делай тему буквально
про телефоны 1950-х — только тонкий намёк в деталях (например, в том, как
показан статус подключения).

Не используй: тёплый кремовый фон с классическим серифом и терракотовым
акцентом; почти-чёрный фон с одним ядовито-зелёным/алым акцентом;
фиолетово-синий градиентный hero. Это клише генеративного дизайна,
нужен другой характер.

Макет: тёмный левый сайдбар с навигацией (фиксированный), светлая рабочая
область справа. Один акцентный цвет для кнопок/ссылок/активных
состояний — не ярко-синий и не ярко-зелёный (зелёный зарезервирован
только для статуса «бот подключён» — это должно читаться буквально, не
декоративно). Числа, телефоны, даты, технические статусы — моноширинным
шрифтом с выровненными цифрами. Заголовки страниц и имена ботов — шрифтом
с характером (не тот же гротеск, что и весь остальной интерфейс).

Сделай следующие экраны:

1. **Вход** — email + пароль, карточка по центру пустого фона.

2. **Список ботов** (владелец видит один или несколько своих) — таблица:
   имя бота, статус подключения, номер телефона, кнопка «Открыть».
   У бота может быть бейдж «на паузе». Продумай, как показать статус
   подключения не просто цветной точкой — у статуса реально 5 состояний
   (подключён / ждёт QR / подключается / переподключается-авария /
   никогда не подключался), а не 3 — точка это не покажет.

3. **Дашборд администратора платформы** (видит все боты всех клиентов
   сразу, десятки строк) — вверху сводные цифры (всего ботов, подключено,
   требуют внимания), ниже та же таблица статусов, но проблемные боты
   отсортированы ВЫШЕ здоровых — это экран для быстрой диагностики, не
   для любования.

4. **Экран одного бота, вкладка «Обзор»** — сверху общая шапка с именем
   бота и вкладками (Обзор / Промпты / Товары / Настройки / Документы /
   Чёрный список / Песочница). Само содержимое вкладки «Обзор» в двух
   состояниях: (а) номер ещё не привязан — крупный QR-код и инструкция
   отсканировать в WhatsApp; (б) привязан — номер телефона + кнопка
   «Отключить».

5. **Вкладка «Настройки»** — форма из нескольких смысловых секций:
   переименование бота; батчинг (сколько ждать перед ответом); хендофф
   (через сколько минут молчания менеджера бот забирает диалог обратно);
   напоминания молчащему клиенту (переключатель + задержка + текст);
   выбор модели LLM (закрытый список, не свободный ввод); лимит размера
   медиа; реакция эмодзи на входящее фото/видео (переключатель).

6. **Вкладка «Товары»** — таблица товаров (миниатюра фото, название,
   цена, артикул) + форма создания/редактирования: название (обязательно),
   цена, артикул, описание, загрузка НЕСКОЛЬКИХ фото с возможностью
   удалить лишние (минимум одно фото обязательно).

Общие требования:
- Русский язык интерфейса везде (реальные тексты, не лорем-ипсум).
- Пустые состояния (например, список ботов без единого бота) — со
  своим текстом-приглашением, без дублирующей кнопки, если способ
  добавить элемент уже есть в постоянно видимом месте экрана.
- Опасные необратимые действия (например, удаление товара) визуально
  отличаются от обычных (например, более спокойное «Отключить» номер —
  это обратимое действие, разница в серьёзности должна быть видна).
- Широкие таблицы должны корректно скроллиться горизонтально внутри
  своего контейнера, не ломая всю страницу, на узком экране.
